# 剧情与进度（narrative 维护）

世界观与基调以 `docs/design.md` 第 0 节"第七中继站"为准（已确认）。本文件放展开内容与草案，确认后的结论回写到 design.md。

本文件**不定任何数值**：凡是"回多少、给什么、概率多少"都写作"designer 待定"。标注"建议"的只是叙事节奏上的默认值，可由 designer / 用户改。

## 1. 一局 = 一个夜班

### 1.1 叙事框架
- 22:00 接班，06:00 交班。一局就是这一夜。
- 第七中继站是一条山区线路的末端。夜里杂波沿线路从远处爬过来；你在桌上的**线路图**（钉在示波器旁的一张蓝晒图）上一段一段地清理它们。
- 线路图上每个**区段**是一个节点。走到哪个节点，桌上就发生哪件事；**你始终坐在工作台前**，不"出门"。节点只改变桌上出现的东西（来电、器材柜、抽屉里的物件）。
- 天亮（打完最后一段）= 交班，本局胜利；线路完整度归零 = **线路中断**，本局结束。两种结局都写一页值班日志。

### 1.2 线路图与推进
- 线路图从站点向外画成一条主线，途中有岔线。每走一步，在面前可选的 1–3 个区段里选一个（形式待用户决定，见看板）。
- 当前原型的 `run.json` 线性 4 场仍然成立：等于每一步只有一个选项、全是杂波区段。
- 墙上挂钟随节点前进（只做表现，22:00 → 06:00 平均分配到各步）。**时间是否成为资源**（例如检修要花时间、天亮前打不完会怎样）属于玩法选择，已列入"待用户决定"；默认不是。

### 1.3 节点类型（叙事侧）

| 类型 | 线路图符号 | 桌上发生什么 | 机制 |
|---|---|---|---|
| 杂波区段（战斗） | 锯齿 | 接收机响起告警，屏幕上显出杂波 | 现有战斗 |
| 强杂波区段（精英） | 双锯齿 | 告警灯常亮不灭；同上 | designer 待定（更强敌人 + 更好的奖励） |
| 检修 | 扳手 | 打开机箱背板：换电子管、重焊接点、拧紧接地线 | designer 待定（恢复完整度 / 改造一张卡 二选一之类） |
| 器材柜 | 钥匙 | 打开墙边的器材柜，里面有前辈留下的旧零件 | designer 待定（遗物） |
| 卡片匣 | 方孔 | 翻档案柜里的空白卡和旧卡 | designer 待定（加卡 / 删卡） |
| 来电 / 事件 | 电话 | 电话、电传、广播、抽屉里的东西——见 §3.3 | 每个事件自带选项，效果 designer 待定 |
| 源头（Boss，未来） | 圆圈 | 线路图边缘画不下的那一点 | designer 待定 |

- 战斗之后的"奖励"（选卡等）在叙事上是：**杂波消散后，接收机里残留一段干净的波形，可以打成一张新卡**。具体给什么归 designer。
- 原型阶段建议只做 杂波区段 / 检修 / 器材柜 / 来电 四种，其余等内容够了再加。

### 1.4 一夜的节奏（建议）
- 上半夜：嗡鸣体、尖啸者——近处的、熟悉的电器噪声。
- 后半夜：潮汐巨像——远处的长波，开始"像在呼吸"。
- 黎明前：干涉双子——两路信号在拍频，节奏开始像某种呼号。
- 将来的源头放在最后一段，日志里称它为"线路尽头"。

## 3. 值班日志

### 3.1 日志本
- 桌上一本硬皮值班日志，横格纸，每页顶部印"第七中继站 值班记录"。
- 一条记录 = **时间 + 一到两行短句 + 署名**。不写形容词堆砌，不写心理活动，像真正的值班记录那样只记事实；诡异感来自事实本身。
- 署名：你写的署"值班员"（或玩家的呼号缩写）；局外剧情会出现**前任值班员**、**日班**和**一行不是任何人写的字**。
- 字数：每行尽量 ≤ 16 个汉字，一条最多 2 行。数字（完整度、区段数）由游戏填入，文案里只写占位符。

### 3.2 什么时候写
| 时机 | 写什么 | 来源 |
|---|---|---|
| 接班（局开始） | 时间、天气/底噪一句、本夜第几班 | 模板，按解锁进度换句 |
| 每个区段结束 | 杂波名、一句处理记录 | 按敌人取模板 |
| 检修 / 器材柜 / 事件 | 选了什么，一句 | 节点或选项自带 |
| 交班（胜） | 小结：清理区段数、剩余完整度、一句 | 模板 + 占位符 |
| 线路中断（负） | 中断时间、最后一句 | 模板 |
| 解锁（局外） | 剧情条目，夹在下一次接班前 | §4 unlocks |

占位符：`{time}` `{shift}` 第几个夜班 `{enemy}` `{integrity}` `{cleared}` 已清理区段数 `{callsign}` 站呼号。

### 3.4 局外主线：呼号的回声

#### 核心秘密（不在游戏里直接说出）
- 1957 年，第七中继站参与过一次向深空发射实验信号的项目：用站呼号 `{callsign}` 作为识别码，连续发送了一夜。项目记录写着"无回波"。
- 二十多年后，回波到了。它在大气底噪里长成了杂波；它们沿着线路往回走，**是在回家**。
- 源头就是那次发射本身的回声。它不恨任何人，它只是在重复它学会的唯一一句话。

#### 揭示顺序（每步一次性解锁，存进度文件）
| # | 触发 | 解锁什么 | 玩家知道了什么 |
|---|---|---|---|
| U0 | 第一次开局 | 前任的交接留言（夹在日志本第一页） | 这里有个前任，站要关了 |
| U1 | 第一次线路中断 | 下一夜接班前出现"日班留言"（样例 11） | 有东西在你的日志里写字 |
| U2 | 第一次打到干涉双子 | 该战后日志多一行："拍频节奏像呼号。"（下面附一行该呼号的莫尔斯码） | 杂波在发你们站的呼号 |
| U3 | 第一次交班（胜） | 器材柜里出现"旧档案"事件（E3 的前置） | 有 1957 年的记录 |
| U4 | 完成 3 个夜班（不论胜负，建议值） | 总局来函事件：中继站关闭日期 | 时间不多了；是谁要关它 |
| U5 | 打开过 E3 并播放磁带 | 杂波意图里偶尔出现一段呼号节奏的波形（designer 设计这段波形） | 不只是巧合 |
| U6 | 击败源头（未来） | 结局条目；"回应 / 静默"的最终选择（待用户决定是否做双结局） | 它在回家 |

- 触发都只看结果，不要求玩家做特定操作；一局里最多插入一条解锁条目，避免剧情挤在一起。
- 呼号节奏的想法：呼号的莫尔斯码（点 = 短脉冲，划 = 长脉冲）可以直接做成一段杂波波形，玩家在接收屏上"看见"自己站的名字。波形归 designer。

### 3.5 事件草稿
效果全部 designer 待定；括号里只写叙事上希望的"倾向"，供 designer 参考。

**E1 电话铃** `midnight_phone`（任何夜班可出现）
> 桌上的内线电话响了。这条线二十年没人打过。

- **接听**　→ 听筒里只有底噪，然后有人很慢地念出本站呼号。
  （倾向：得到一点东西，付出一点完整度）
- **拔掉电话线**　→ 安静了。
  （倾向：无事发生，最安全）
- **接到录音机上**　→ 磁带转了一夜。
  （倾向：现在没好处，日后某个事件/解锁会用到——可作为 U5 的另一条路径）

日志：
> {time}　内线来电。接听，无人说话。

**E2 前任的卡** `predecessor_card`（U0 之后可出现）
> 抽屉最里面有一张打孔卡，背面用铅笔写着：别用。

- **放进卡片匣**　→ 卡片匣多了一张卡。
  （倾向：一张强但有代价的卡）
- **放回抽屉**　→ 什么也没变。
- **在背面写上日期**　→ 你在"别用"下面写了今天的日期。
  （倾向：纯叙事，日后前任相关事件会提到）

日志：
> {time}　抽屉里有张旧卡。写着别用。

**E3 旧档案** `archive_1957`（U3 之后，在器材柜节点出现，一次性）
> 器材柜底层有一盘磁带，盒上贴着：1957.10　深空实验　无回波。

- **播放**　→ 一夜的呼号，一遍又一遍。最后一分钟，背景里有别的东西也在念。
  （倾向：触发 U5；有代价）
- **倒着播放**　→ 呼号倒过来，听起来像接收屏上的嗡鸣体。
  （倾向：纯叙事或小收益）
- **封存**　→ 磁带放回原处。
  （倾向：无；以后还能再遇到）

日志：
> {time}　找到一盘 1957 年的磁带。
> 　　　 标签写着：无回波。

## 4. 数据格式草案
以下为建议格式，由 gameplay 实现加载与校验（看板已请求）。字段名可由 gameplay 调整，改了请回写这里。所有文本直接写在数据里，之后再做本地化。

### 4.1 事件 `data/events/<id>.json`
```json
{
	"id": "midnight_phone",
	"title": "电话铃",
	"prop": "phone",
	"requires": { "unlocked": ["U0"], "not_unlocked": [] },
	"once_per_run": true,
	"once_ever": false,
	"text": "桌上的内线电话响了。这条线二十年没人打过。",
	"choices": [
		{
			"id": "answer",
			"label": "接听",
			"result": "听筒里只有底噪，然后有人很慢地念出本站呼号。",
			"effects": [],
			"unlock": null,
			"log": "{time}　内线来电。接听，无人说话。"
		}
	]
}
```
- `prop`：桌上出现的物件（phone / teletype / drawer / tape / cabinet / letter），由 ui 在 `Assets` 里登记。
- `effects`：与卡牌 `effects` 同一套注册表；具体类型与数值 designer 待定。可为空（纯叙事选项）。
- `requires` 只引用解锁 id；出现权重如需要由 designer 另加字段。
- `unlock`：选这个选项会触发的解锁 id（如 E3 播放 → `U5`）。

### 4.2 节点类型 `data/config/nodes.json`
```json
{
	"nodes": [
		{ "type": "fight",  "name": "杂波区段", "icon": "node_fight",  "log": null },
		{ "type": "elite",  "name": "强杂波",   "icon": "node_elite",  "log": null },
		{ "type": "repair", "name": "检修",     "icon": "node_repair", "log": "{time}　打开背板检修。" },
		{ "type": "cabinet","name": "器材柜",   "icon": "node_cabinet","log": "{time}　打开器材柜。" },
		{ "type": "cards",  "name": "卡片匣",   "icon": "node_cards",  "log": "{time}　整理卡片匣。" },
		{ "type": "event",  "name": "来电",     "icon": "node_event",  "log": null }
	]
}
```
- 每种节点的机制（检修给什么、器材柜几选一）由 gameplay + designer 在代码/规则数据里定义，这里只放名称、图标与默认日志句。
- `name` 是给线路图悬停用的；按"少文字"原则，线路图本身只画符号。

### 4.3 一局的线路 `data/config/run.json`（扩展，兼容现有格式）
```json
{
	"shift_start": "22:00",
	"shift_end": "06:00",
	"steps": [
		[{ "type": "fight", "encounter": "01_drone" }],
		[{ "type": "repair" }, { "type": "event" }],
		[{ "type": "fight", "encounter": "02_shrieker" }],
		[{ "type": "cabinet" }, { "type": "event" }],
		[{ "type": "fight", "encounter": "03_tide_colossus" }],
		[{ "type": "repair" }],
		[{ "type": "fight", "encounter": "04_twins" }]
	]
}
```
- `steps` 每一项是这一步可选的节点（1 个 = 没得选）。旧格式 `"encounters": [...]` 继续支持，等价于每步一个 fight。
- `event` 节点不写具体事件时，从满足 `requires` 的事件里抽（种子可复现）；也可写 `"event": "archive_1957"` 指定。
- 是否改成随机生成的分叉地图，取决于"待用户决定"里的地图形式；本格式只描述固定线路。
- 上例中非战斗节点的位置只是叙事示意，放几个、放哪里归 designer。

### 4.4 值班日志模板 `data/log/entries.json`
```json
{
	"entries": [
		{ "id": "start_default", "when": "shift_start", "requires": {}, "lines": ["山里起雾，底噪偏高。"], "sign": "operator" },
		{ "id": "start_late",    "when": "shift_start", "requires": { "min_shift": 5 }, "lines": ["第 {shift} 夜。咖啡还是凉的。"], "sign": "operator" },
		{ "id": "fight_drone",   "when": "after_fight", "requires": { "encounter": "01_drone" }, "lines": ["五十赫左右的嗡声。已消除。"], "sign": "operator" },
		{ "id": "end_win",       "when": "shift_end",   "requires": {}, "lines": ["清理 {cleared} 段。完整度 {integrity}。", "天亮了。交班。"], "sign": "operator" },
		{ "id": "end_cut",       "when": "shift_cut",   "requires": {}, "lines": ["线路中断。", "最后一段读数：{enemy}。"], "sign": "operator" }
	]
}
```
- `when`：shift_start / after_fight / node / shift_end / shift_cut / unlock。
- 同一时机有多条满足条件时，取 `requires` 最具体的一条（或按种子随机，gameplay 决定）。
- `sign`：operator / predecessor / day_shift / none。时间 `{time}` 由游戏按挂钟自动加在行首，模板里不写。

### 4.5 局外解锁 `data/story/unlocks.json`
```json
{
	"unlocks": [
		{ "id": "U0", "trigger": { "type": "first_run" }, "log": ["交接：器材柜钥匙在左边抽屉。", "卡片匣别弄乱。"], "sign": "predecessor" },
		{ "id": "U1", "trigger": { "type": "first_cut" }, "log": ["线路已复位。", "夜班日志最后一行不是你的字。"], "sign": "day_shift" },
		{ "id": "U2", "trigger": { "type": "reach_encounter", "encounter": "04_twins" }, "log": ["拍频节奏像呼号。"], "sign": "operator" },
		{ "id": "U3", "trigger": { "type": "first_win" }, "log": [], "sign": "none" },
		{ "id": "U4", "trigger": { "type": "shifts_completed", "count": 3 }, "log": [], "sign": "none" },
		{ "id": "U5", "trigger": { "type": "choice", "event": "archive_1957", "choice": "play" }, "log": [], "sign": "none" }
	]
}
```
- 解锁状态存在 `user://progress.json`（与引导进度同一文件，经 `Platform`），只增不减。
- 一局最多插入一条解锁日志；多条同时满足时按 id 顺序排队到下一夜。
- `{callsign}` 等全局文本常量建议放 `data/story/strings.json`（例如 `{ "callsign": "待定" }`）。
